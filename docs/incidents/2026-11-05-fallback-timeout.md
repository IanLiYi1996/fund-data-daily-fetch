## 代码修复

`lambda/fund-fallback-fetcher/handler.py`：

- 缺口回填先于货基值核验，FOF 在候选中优先。
- 128 只一批，抓取、去重、REIT 隔离、提交后再抓下一批；只更新已成功提交的
  去重集合和行数，失败的后续批不会抹掉前面的进度。
- 同时使用运行时剩余时间和 810 秒软预算，预留 90 秒收尾；
  超时前取消排队请求、等待有超时限制的在途只读请求、提交已完成数据，
  明确返回 `complete=false / success=false / pending`。
- 一次有界读取最新基金名册，复用已有净值对；不再在两个阶段重复读全年名册。
  最近十四天名册为空时才退回历史查找，不能把源名册缺失报告成零缺口。
- 货基核验依然覆盖五天、按最新 `ingested_at` 比较；分批提交纠正，
  阶段预算不超过 120 秒。未完成核验不能报告整体成功。
- HTTP 状态、上游错误码、返回日期范围及有限净值校验失败都显式报告，
  不伪装成“上游没有数据”；真正空数据保持空数据。
- 保留海外晚披露、近期首次/恢复披露探测、周末货基范围、REIT 当日隔离。
- 阈值、FOF 两个交易日滞后及生命周期/豁免逻辑没有修改。

`lambda/freshness-check/handler.py`：

- 从补采 task 的真实退出结果识别超时、部分完成、源错误、货基核验未完成，
  即便外层工作流是 `SUCCEEDED` 也直接报警。
- 兼容以前没有 `complete` 字段但确实成功的旧结果。
- 不修改历史执行记录，不通过触发整个跨资产工作流刷掉旧失败。
